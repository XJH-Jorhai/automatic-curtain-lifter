## 2. 当前 DP 冻结表

初始截图、调试 JSON、数据点 XLS、产品串口协议和生成 SDK 均为 DP2 步长 10。控制台修改后下载的新调试 JSON 已确认 DP2 步长为 1、默认值为 `0`，其余 DP/PID 未变化；XLS、产品协议和 SDK 尚需重新生成，旧版材料继续保留用于追溯。

| DP ID | code | 方向 | 类型 | 当前范围 | STM32 语义 | 处理结论 |
|---:|---|---|---|---|---|---|
| 1 | `control` | 下发/上报 | enum | `open=0`、`stop=1`、`close=2`、`continue=3` | 打开、停止优先、关闭、同一上电会话内恢复上次方向 | 可用于首轮联调 |
| 2 | `percent_control` | 下发/上报 | value | 0–100，步长 **1**，默认值 0 | 目标位置 | 控制台和新 JSON 已修正；等待重新生成 XLS、协议和 SDK |
| 101 | `percent_state` | 只上报 | value | 0–100，步长 1 | 实际/估算当前位置 | 保留，运行中限频上报、停止时立即上报 |

当前产品没有行程校准、方向反转、故障位和位置可信度 DP。它们不能被文档假定为“已有”：首轮联网 PoC 可由 STM32 本地完成校准和方向设置；若公版面板提供相应标准 DP，再在控制台增加并重新生成全部资料。

### `continue` 的安全定义

`continue` 只允许恢复“本次上电后、被明确 `stop` 中断、且方向和位置仍可信”的动作。上电后无历史停止动作、发生驱动故障、位置不可信、校准中或目标已到达时必须拒绝运动，只上报当前状态。不得把 `continue` 简单映射为固定方向。

## 3. 串口基线

- 电平：3.3 V UART。
- 参数：9600 bit/s、8 数据位、无校验、1 停止位、无流控。
- 帧头：`0x55 0xAA`。
- 长度：2 字节大端。
- 校验：从帧头开始逐字节求和，对 256 取余。
- 模组发给 MCU 的协议版本字节为 `0x00`；MCU 上报使用 `0x03`。
- MCU 接收必须逐字节喂给 SDK，`wifi_uart_service()` 必须在主循环持续执行，不能只在“收到一帧”时调用。

首轮必须实现的命令字：

| 命令字 | 功能 | STM32 要求 |
|---:|---|---|
| `0x00` | 心跳 | 首次回复 0，其后回复 1；记录模组在线状态 |
| `0x01` | 查询产品信息 | 返回 PID、MCU 版本和特殊配网模式 |
| `0x02` | 查询模组工作方式 | 当前由 MCU 管理配网键和状态灯 |
| `0x03` | Wi-Fi 状态 | 只更新联网状态，不直接驱动电机 |
| `0x04/0x05` | 重置/切换配网 | 台架由 PA2/PA3 调试串口显式发起；产品固件由独立 `NETCONTROL_BTN`（PC13）受控触发，长按时序与防误触待实现 |
| `0x06` | DP 下发 | 校验长度、类型、范围和运动安全条件后入队 |
| `0x07` | DP 上报 | 上报已接受/已实现的状态，不做无条件回显 |
| `0x08` | 查询全部状态 | 至少回复 DP 1、2、101 的当前一致快照 |
| `0x0E` | Wi-Fi 产测 | 当前生成配置已启用；上电初始化 5 秒后再调用 |

MCU OTA 宏在当前生成配置中未启用，不能把双固件 OTA 当作已完成能力。

首版主板另保留 CN1 GH1.25 8P 调试口：PA2/PA3 调试 UART 通过 G030 专用透明桥接固件转发至 PA9/PA10 的 T1-3S 用户 UART，CN1.8 引出 CEN 供下载复位。这是烧录模式，须停用上述 9600 波特日常协议和调试日志；与来货直接串口烧录授权记录（历史附件未随公开候选提供）分开验收。针脚与工具实测步骤见[烧录桥接方案](../hardware/schematic-review/tuya-programming-bridge.md)。

## 4. T1-3S 硬件约束

### 4.1 接口

| T1-3S 引脚 | 名称 | 连接建议 |
|---:|---|---|
| 8 | 3V3 | 独立、低阻抗 3.3 V 电源 |
| 9 | GND | 与 STM32 共地；电机大电流回流分区 |
| 15 | RX1 | 接 STM32 USART1_TX |
| 16 | TX1 | 接 STM32 USART1_RX |
| 3 | CEN | 内部上拉；V3 首版引至 TP4 和 CN1.8，可由开漏/三态方式拉低复位 |
| 1 | RST | 低电平复位；首轮预留测试点，不与 CEN 同时强驱动 |

TX/RX 必须交叉连接。不要使用 TX2/RX2（引脚 11/12），它们用于模组内部日志。禁止 5 V UART 直连。

### 4.2 电源和布局

- 工作电压 3.0–3.6 V，典型 3.3 V。
- 资料中的最坏典型工作电流达到 394 mA；开发板电源至少按 500 mA 能力，工程样机建议给模组留 600 mA 级以上余量，整板 Buck 建议按不低于 1 A 重新选型并实测瞬态。
- 模组近端放置 100 nF、10 µF，并预留 100 µF 级低 ESR 储能；最终值以示波器测得的 3.3 V 跌落和纹波为准。
- 板载 PCB 天线区域禁止走线和覆铜；天线与电机、齿轮、金属外壳等金属件至少保持 15 mm 距离。
- 模组尺寸约 16.0 mm × 24.0 mm × 2.8 mm；封装 keep-out 区不得上锡、走线。
- P6、P8、P9、P24、P26 上电可能出现毛刺，不用于直接控制电机使能、方向或停止信号。

## 5. 自动生成 SDK 审查结果

生成 SDK 标头版本为 2.6.2（2026-02-04）。它是协议模板，不是可直接编译的 STM32 工程：

1. `protocol.c`、`mcu_api.c` 中保留多处有意设置的 `#error`，要求开发者完成 UART 发送、接收喂数、协议初始化、主循环服务和全量状态上报。
2. `dp_download_control_1_handle()` 与 `dp_download_percent_control_2_handle()` 的业务分支为空，模板随后立即回显收到的 DP。这会让 App 误以为电机已经接受或完成命令。
3. `all_data_update()` 未实现，模组执行 `0x08` 全量查询时不能得到有效状态。
4. 当前配置为 `CONFIG_MODE_SPECIAL`，防误触特殊配网；低功耗长连接、MCU OTA、时间、天气、流服务、BLE 扩展等宏均未启用。
5. `WIFI_TEST_ENABLE` 已启用，量产/台架 Wi-Fi 产测路径需要实现。
6. 未启用 MCU OTA 时缓冲区很小：接收 16 字节、处理 24 字节、发送 48 字节。新增功能前必须重新核对最大帧长，不能盲目扩大而不做边界测试。
7. `offline_voice_word_zh_cn.h` 是未启用的通用离线语音词表，本项目不使用。

### 正确的 DP 处理顺序

```text
收到并校验 DP → 转换为平台无关命令 → 运动层安全检查 → 入队/拒绝
→ 只在状态真正改变后上报 DP 1/2/101 → 停止、软件端点、故障时立即上报最终快照
```

UART 中断只做收字节入环形缓冲，不调用 DP 上报函数；协议解析、命令派发和状态上报在主循环任务中完成。
