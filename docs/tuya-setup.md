# 涂鸦依赖与自己的产品配置

Product 需要合法取得的涂鸦 MCU SDK。SDK、模组授权包、云账户、模组固件及 EEPROM 转储不随仓库分发。项目 MIT 许可不授予这些第三方材料的再分发权。

1. 在自己的涂鸦开发者账户创建对应窗帘产品，使用自己的 PID 和匹配 T1-3S 的模组固件/授权。
2. 按 [软件设计](software-design.md) 的 DP 表配置控制枚举、目标百分比、当前进度和上下端保存事件。DP1、2、101、102、103 的编号、类型、枚举顺序必须与适配实现一致；面板分别绑定目标和实际进度。
3. 从自己的产品生成 MCU SDK，将以下八个文件放在一个本地目录：`mcu_api.c/.h`、`protocol.c/.h`、`system.c/.h`、`tuya_type.h`、`wifi.h`。保留 SDK 原始版权与许可。
4. 用 `build.ps1 -TuyaSdkDir <本地SDK目录>` 指定来源。构建脚本复制到构建目录并执行适配，不修改原始下载目录。
5. 运行完整主机回归，再验证自己的模组/面板交互。

当前移植器针对 2026-07-16 取得的模板快照（SDK 2.6.2，模板标记 2026.02.04）。它严格检查预期文本，较新模板可能失败。失败时对照 `firmware/g030_tuya/prepare_tuya_sdk.py` 的替换规则适配；不要直接删除断言或复制作者 PID。取得兼容 SDK 的过程尚未由第二个账户独立复现，这是当前复刻限制。

没有 SDK 仍能运行 `python tools/test_host.py` 的独立运动/EEPROM/校准回归；这不等于完整 Product 构建。当前不提供包含作者 SDK/PID 的固件二进制。

完整产品与面板设计过程见 [涂鸦接入设计方法](tuya-design-guide.md)。尤其注意：新生成 SDK 若已包含校准 DP，需调整旧模板追加逻辑，不能重复定义。
