# 800 rpm短试探：编译、烧录与启动验证（2026-10-24）

用户观察720 rpm已出现丢步，要求考虑提高至800 rpm以增加识别余量，同时缩短试探总时间，减少失速嗡鸣。另确认“不会叫”指原来的开机旋律/提示音。

## 参数与行为

| 用途 | 当前设置 |
|---|---|
| 方向试探A/B | `LIFT_PROBE_HZ=21333`，名义800 rpm |
| 单向试探上限 | `LIFT_PROBE_MS=1500`，原2500 ms |
| 加速、稳定等待 | 仍为1000 ms、150 ms，余下约350 ms采样 |
| 失速确认 | 仍为80 ms，确认后立即结束当前方向 |
| 换向等待 | 仍为200 ms；双向均跑满合计约3.2秒，原约5.2秒 |
| 找底、正常下放 | 各自独立配置，均仍为9600 STEP/s，约360 rpm |
| 上卷/上端归零 | 仍为2667 STEP/s，约100 rpm |

电流与TRQ阈值、正常TRQ所需16个稳定样本和各项停止保护保留。缩短后满速停留由约1.5秒变成约0.5秒，检测到失速可提前结束；物理嗡鸣时长和识别稳定性仍需现场验证。证据不足时停止，不强行确定方向。

标定版本更新为5，启动忽略旧版标定，下次运动请求重新试探。不擦除外部EEPROM、不上电自动运动。

1 MHz定时基准将名义800 rpm量化为23 µs半周期，理论STEP约21739/s，即约815.22 rpm。实际转速未测量，主机模拟机构不代表真实负载性能。

## 开机旋律原因

当前Product的CMake源文件列表不包含 `music.c`、旧版 `motor.c` 和音乐播放器，启动入口也没有播放调用；ELF符号检查再次确认 `Motor_PlayText` 等入口缺失。因此开机无旋律是软件未接入该功能，并非发声电流不足。正常运动仍通过PA4低选择原约1.50 A满量程档，未提高电流或恢复音乐动作。旧音乐记录仍保留在EEPROM原槽位，本轮不访问。
