## 模式与限制

波特率已重新查到原始证据：[核查记录](../../hardware/test-records/2026-10-21-tuya-baud-audit.md)。2026-09-24成功的bk_loader下载明确使用115200；当前云模组保存的烧录/授权设置均为115200。历史授权成功，但未找到该阶段波特率的独立日志；9600是已验证的烧录后MCU通信速度。暂不改成9600，完整桥接烧录授权仍以工具实测结果为准。

`TuyaBridge` 是独立构建，复位后始终进入桥接；普通 `Debug` / `Release` 保留原电机应用。桥接通过启动阶段的 USER CODE 分支进入，USART1的专用初始化位于 `App/tuya_bridge.c`，不改变普通应用的 `.ioc` 外设配置。

- PC → USART2 PA3 → USART1 PA9 → T1-3S RX1。
- T1-3S TX1 → USART1 PA10 → USART2 PA2 → PC。
- 两侧固定 **115200、8N1、无流控**；双向独立2048字节环形缓冲（各可用2047字节），非阻塞轮询。
- 不插入日志、提示符、回显或转义；包括0x00、0xFF在内的全部字节均按原样传输。没有串口退出命令。
- ENABLE、nSLEEP、STEP、DIR和电流选择保持低；不初始化运动应用、不处理本地开关、不播放启动音乐、不访问EEPROM。
- 初始化完成后停止中断服务，持续轮询两端。LED常亮表示初始化完成；修正版遇到UART帧/噪声/溢出错误会清除错误、丢弃受影响方向缓存并继续接收；软件缓冲满时丢弃新字节并计数，不锁死、不熄灯。只有UART初始化失败才熄灯停止。LED只表示本地状态，不代表模组握手成功。
- SWD可查看 `tuya_bridge_fault`（0正常，0x300为模组UART初始化失败）、`tuya_bridge_rx_errors`、`tuya_bridge_queue_drops`、`tuya_bridge_last_error`及两个发送字节计数。last_error的0x100前缀为PC侧、0x200为模组侧，低四位是UART错误标志，0x10为队列满。错误计数不代表当前已经停止。烧录中不要暂停MCU。

**固定波特率是当前验收前提。** 修改PC的COM波特率不会通知STM32；不支持自动跟随烧录工具的变速。需核对握手、下载和授权阶段均为115200。若工具强制切换至921600、1500000或授权9600，本版本不能完成整套流程，应先停止并调整方案，不能只修改PC设置后继续尝试。历史通用MCU协议是9600，本桥接镜像也不能直接用于烧录后9600协议验证。

## 构建与部署

本次修正版成功使用现有 `flash_bounded.py --elf ../../work/g030-mainboard-build/TuyaBridge/g030_mainboard.elf --words 16`，在已配置pyOCD依赖的Python环境运行。参数含USB v2、50kHz、单包、关闭延迟传输；复位暂停后64字节RAM上传并回读校验，再按扇区烧录、完整Flash回读和软件复位。普通flash.ps1本次失败，不能将其作为这次成功命令。

在本目录执行（本次已执行TuyaBridge烧录；以下供后续重建/部署）：

```powershell
.\build.ps1 -Configuration TuyaBridge
.\flash.ps1 -Configuration TuyaBridge
```

若受限终端的LOCALAPPDATA指向隔离目录，构建加参数：

```powershell
.\build.ps1 -Configuration TuyaBridge -ArmBin '[LOCAL_PATH] GNU Toolchain\15.2 Rel1\bin'
```

产物：`../../work/g030-mainboard-build/TuyaBridge/g030_mainboard.elf`、`.hex`、`.bin`。这些是 **STM32桥接固件**，不能选作涂鸦模组固件。恢复电机应用须重新给STM32烧入 `Debug` 镜像；单纯复位仍是桥接。原100rpm产物另备份在 `../../work/mainboard-before-tuya-bridge/`。

## 当前实板连接和操作顺序

接线以 [PINOUT.md](PINOUT.md) 的2026-10-20冻结网表为准；2026-10-11旧文档的CN1串口/SWD编号已经过期。

| 当前CN1针号 | 连接 |
|---|---|
| 2 GND | 串口地 |
| 4 DEBUG_TX | 外部串口RX |
| 5 DEBUG_RX | 外部串口TX |
| 8 TUYA_CEN | 调试板SW1，复位涂鸦模组 |
| 3 MCU_NRST | 调试板SW2，复位STM32 |

主板正常12V供电，串口为3.3V TTL；CN1.1只作电平参考，不把串口适配器的电源输出并入主板3V3。使用现有调试板时保持GH线1→1连接。SW1与SW2作用不同。

1. 将STM32桥接镜像部署到主板；关闭串口监视器/串口插件的端口连接，避免占用或主动发命令。当前端口须现场确认，历史COM3/YOUR_SERIAL_PORT不能作为自动选择依据。
2. 确认STM32桥接正在运行、LED常亮。手动拉低再释放涂鸦CEN是历史已验证的正常烧录操作，不能要求复位STM32来绕开该步骤。修正版必须允许此过程中出现的串口错误自动恢复。
3. 在涂鸦“生产解决方案 → 云模组”选择正确产品与模组固件、烧录授权工序和实际COM端口，核对各阶段波特率。凭证只在官方工具中输入。
4. 启动工具等待连接后，按一下再松开SW1，将模组CEN短暂拉低后释放，复位启动进入握手。不要按SW2，也不要让调试器暂停STM32。若工具要求再次复位模组，可按其提示操作SW1。
5. 由用户完成写入、CRC校验及授权，并记录工具结果、实际波特率和是否有变速。失败时保留不含密钥的错误摘要；若修正版LED熄灭，属于异常，需读取状态排查，不能把CEN导致熄灯视为正常流程。
6. 完成后关闭工具。下一步开发主板9600协议适配，再验证心跳、产品初始化和DP；恢复旧电机镜像只恢复本地运动，尚不会处理涂鸦协议。

官方接线参考：[T1系列产测和接线说明](https://developer.tuya.com/cn/docs/iot/T1-testing?id=Kefsmduu2es6x)。官方不同工具/平台可能使用不同速度，不能用其他系列的默认值推断当前云模组工具参数；例如 [TuyaOpen烧录说明](https://docs.tuyaopen.ai/zh/docs/tyutool/flash) 的T1默认下载速度为921600，因此不适合直接套用本桥接配置。

## 验证边界

最新：用户换回开发板USB串口后，确认端口COM3（0D28:0204）。在同一STM32固件上，5轮4KB双向传输（含3轮一次性整块发送）和6轮双队列回绕全部通过，逐轮错误/丢弃增量为0。原COM4整块缺尾问题在COM3未复现。复位后独立验证正常115200直通、错误计数0。后续工具应选择COM3；涂鸦固件烧录和授权仍由用户操作，尚未验证成功。

2026-10-21有线COM4诊断已完成：4KB分段双向逐字节测试、6轮4KB双队列回绕全部通过，官方bk_loader经桥接读取模组首4KB成功。STM32修正版不再因UART错误清空此前有效队列，增加分方向错误/丢字节/高水位计数和SWD隔离测试模式。测试后已复位恢复正常115200桥接。

仍存在阻断：COM4一次write发送4096字节，STM32隔离捕获只收到3904字节正确前缀，无FE/NE/ORE/PE或软件丢弃；64字节每8ms或256字节每30ms分段发送完整。DTR=true和64KB驱动缓存未解决。19:50 USB ETW确认4096字节OUT完整成功；另一次隔离测试收到调试器自行返回的两条`<overflow>\0`，对应少128字节。已定位调试器串口固件缓存溢出，不是Windows截短发送；调试器本身尚未修复。不能把桥接测试通过等同于涂鸦烧录授权通过。详见[4KB测试记录](../../hardware/test-records/2026-10-21-tuya-bridge-4kb.md)。
