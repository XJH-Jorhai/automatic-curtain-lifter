# 电机音符与初始化音效（v7）

> 2026-10-24 v2音量试听：用户反馈原开机音量约2/10，希望7/10。本轮保留原EEPROM B1音高、节拍和1177 ms乐谱，将Product音乐改为原约1.50 A工作电流档、正反各5微步往返；7/10为待现场确认的听感目标。每次开机一次、正常结束指令偏移归零，停止和升降优先，启动零写入。见[v2验证记录](../../hardware/test-records/2026-10-24-workmode-v2.md)。下方0.42 A、三微步等内容属于此前版本。

> 2026-10-24：当前[Product产品固件](PRODUCT.md)已恢复从原EEPROM读取并播放一次B1开机旋律，沿用约0.42 A音乐档和正反各3微步，正常升降仍为原约1.50 A档。按键/停止/升降可中断音乐，启动零写入、无重试；见[烧录与验证](../../hardware/test-records/2026-10-24-probe800-music.md)。下文v7串口、保存接口及旧台架接线说明为历史内容，产品仍只开放状态查询和停止命令。

## 已选定的初始化音效：B1

用户已选定“B1 电子色彩 · 利落版”：A10旋律配A3的232 BPM。
2026-10-20实板试听后，用户确认“听起来不错，就这样吧”，当前方案定版。
乐谱为：

```text
T232 C4/16 E4/8 F#4/16 R/16 Ab4/8 G4/16 R/16 B4/16 C5/4
```

7个发声音符、2个休止，共1177 ms（含现有每事件30 ms间隔）。
保持正反各3微步与低电流档。通过一次明确保存事件写入EEPROM；
初始化完成后只读加载并播放一次，不在启动时写入。
`App/music_scores.h`记录选定乐谱及独立的斗地主测试曲。
斗地主仅保留为`MOTOR TUNE`人工测试，不再作为当前启动乐谱。
当前模组未启用，启动音不代表涂鸦联网成功。

业务通过 `music.h` 的 C 接口保存乐谱、播放或停止；串口文本仅保留为台架诊断入口。
按用户最新要求，外设与安全状态初始化完成后，从 EEPROM 加载乐谱并播放一次，
不循环、不自动重试。软件复位也经过该启动路径，因此也会播放一次。
播放时只使用低电流档。当前测试没有连接执行器。

## 业务接口与 EEPROM

```c
#include "music.h"
const char *score = "c4f4g4";
const char *error = Music_SaveScore(score); // 明确配置事件：验证后保存，不播放
// 后续独立的播放事件：
error = Music_PlayStored();                // 播放一次
// 独立的停止事件：
Music_Stop();
```

返回 NULL 表示成功，其他返回值为静态错误字符串。示例的三个调用代表不同事件，
不能把它们放入主循环重复执行。全部从主循环上下文调用，不能在中断中调用。
`Music_GetScore(buffer, capacity)` 按需获取当前乐谱。最多191字节，必须以NUL结束。
音乐解析、每一步正反交替、低电流及故障停止沿用已有播放器。

不注册 EEPROM 周期任务，不在启动时写入。启动的一次播放事件加载两份记录；
后续使用 RAM 缓存。同字符串重复保存不产生任何 I2C 操作。存储或总线错误后只在下一次
显式调用时重新读取，不后台重试。播放期间拒绝保存及读取，避免阻塞安全主循环。
尚未设置有效乐谱时返回 `SCORE_NOT_SET`，不会默认播放内置歌曲。

EEPROM 预留 0x000–0x1FF 两个256字节槽，分别使用前208字节：
16字节头（MSC1、版本、长度、序号、CRC32）和192字节字符串区。
只更新非当前槽：先使其头无效，再逐页比较更新正文，最后提交头并逐页读回。
旧槽保持不变；启动后首次显式加载选择校验、语法均正确的最新记录。
这可恢复到完整旧记录或完整新记录，不承诺在超出 EEPROM 供电规格时绝对可靠。
0x200–0x7FF 不使用，不提供全片擦写。

原先单页60秒限制扩展为**一次逻辑保存**60秒冷却、每次启动最多8次尝试，与原单页更新共享预算。
一次保存最多14次物理页写（含失效头及提交头），相同页跳过；失败也消耗一次预算。
预算保存在RAM，不能阻止反复重启绕过，因此云端同样需要限频；不为维护预算增加 EEPROM 写入。
`EE STATUS attempts`现在统计逻辑保存/单页尝试，`writes`统计完成验证的物理页写。

## 涂鸦 / MQTT 接入预留

当前路径为：服务器 → 涂鸦云 DP → T1-3S 模组 → USART1 MCU SDK →
主循环业务事件 → 上述 C 接口。G030 不直接连接 MQTT。若服务器是自建 MQTT broker，
还需要服务端到涂鸦云的桥接，或支持该 broker 的模组固件，不能直接假定标准模组可订阅任意服务器。
参考[涂鸦 Wi-Fi MCU SDK 基础功能](https://developer.tuya.com/cn/docs/iot/basic-features?id=Kaumiwx9b4kkp)。

后续在产品平台定义独立功能点，具体ID及载荷限制待产品配置确定：

| 业务事件 | MCU 行为 |
| --- | --- |
| 设置乐谱字符串 | 长度检查、拷贝并补NUL，调用 Music_SaveScore；验证成功才确认已保存 |
| 播放请求 | 检查会话与请求ID、过期时间和互锁，再调用 Music_PlayStored |
| 停止请求 | 优先调用 Music_Stop，清除尚未执行的播放事件 |
| 状态查询 | 回报实际播放/故障状态；不能触发播放或保存 |

已有电机控制DP 1/2及位置DP 101不复用为音乐命令。
USART IRQ只收字节；SDK回调校验载荷、复制到有界队列，由主循环执行。
播放请求使用新的请求ID去重，并绑定本次会话；重连/重启的旧请求、retained消息和状态同步
不得触发播放。去重状态放RAM，新的会话握手防止重启后接受旧播放请求。
设置乐谱与播放必须是独立事件，禁止“下载乐谱后自动播放”。
运动忙时拒绝播放，停止优先；保存完成和播放完成分别按实际结果回报。
这些是接入约定，尚未实现云端、DP适配或请求去重；模组未烧固件，本次不做联网测试。

## 实物保存与掉电验证

`music_persistence_check.py --port YOUR_SERIAL_PORT --phase save` 通过诊断适配层调用生产
`Music_SaveScore`，先备份空白 EEPROM，保存原斗地主第一乐句，再重复保存三次。
检查全部读写计数不变、按需回读字符串、CRC和整个 EEPROM 镜像，确认槽外未修改。
这不是周期业务，也不会在脚本里发送播放命令。

确认保存成功后，用户手动断电再上电；此时启动会播放一次。
`--phase after-power` 检查启动加载两次读、零写、缓存字符串、完整镜像，
以及启动播放已正常完成（软件指令计数、停止原因及驱动禁用状态）。
这些状态不能代替现场听音和机械观察。空闲5秒内再核对无读写、无重复播放。
`BOOT` 查询RAM中的本次启动播放结果；`MUSIC GET` 获取缓存，
`MUSIC SAVE <乐谱>`仅供本次调试使用，未来业务直接调用C接口。

## 诊断输入

串口115200 8N1，每行以CR或LF结束，最多191字节。

```text
CHECK c4f4g4
c4f4g4
PLAY C4 F4 G4
PLAY T150 C4/8 D4/8 E4/4 R/8 G4/4.
STOP
```

- `CHECK ...`只解析并报告音符数、总时长、首尾频率，不动作电机。
- `PLAY ...`播放一次；也可直接发送`c4f4g4`或`T150 c4f4g4`。
- 音名A–G，大小写均可，数字是八度：C4为中央C，A4约440 Hz。
- 连续、空格、逗号分隔均可；支持`C#4`、`Db4`、`Bb3`。
- `T120`指定BPM，范围40–300，只能放开头并用空格/逗号与音符分开。默认120。
- 默认四分音符；`/1 /2 /4 /8 /16 /32`指定时值；尾部`.`为附点。
- `R`或`P`为休止符，如`R/8`，不加八度数字；休止符暂停STEP，驱动仍保持低电流使能。
- 音域C3–B5，最多32音/休止符、总时长10秒（含每音后30 ms间隔），不支持无限循环。
- 整行先完整解析，格式错误、越界、过长时拒绝，绝不“先播前半段再报错”。
- `TUNE TEST`是纯内存解析及正反序列自测，不动作电机。
- `MOTOR TUNE`保留此前用户提供的斗地主第一乐句，但也使用新版自动正反交替。

原乐句文字：

```text
T150 E4/4 E4/8 D4/8 C4/4 C4/8 A3/4 D4/8 E4/8 D4/8 E4/8 G3/4.
```

按用户八度更正，以C4为1：第6音为低音6=A3（220 Hz），末音为低音5=G3（196 Hz）。
之前末音G4（392 Hz）高了一个八度；A3原先已是低音6，未再降至A2。
这里的Hz是指令往返频率，实际可听声的主导频率尚未测量。
`music_persistence_check.py`和此前二进制快照保留首次保存/掉电试验的旧乐谱基线，
不要将其用于比较更正后的记录。

Bluejay电调使用的完整RTTTL包含名称、默认参数头等语法；这里按用户所需实现了简写音符文本，
**不宣称兼容完整RTTTL或Bluejay固件格式**。参考：[Bluejay RTTTL工具](https://github.com/bird-sanctuary/bluejay-rtttl-parse)。

## 防止单向累积

已上板验证的版本是“正向一个微步 → 反向一个微步”，用户反馈振动、无持续旋转，
但音量约2/10。当前源码准备的增响版为“正向两个微步 → 反向两个微步”，
`TUNE_SWING_STEPS=2`；已在用户确认就位后烧录并触发一次启动试听。
软件状态显示3960个STEP脉冲、11音正常完成、偏移归零，等待用户评价实际音量。
用户反馈两微步版本音量约4/10，仍无须持续旋转。下一轮源码已改为
`TUNE_SWING_STEPS=3`（正反各三微步），已完成烧录、完整Flash回读和一次启动试听。
同时末音更正为G3；5226个STEP脉冲、11音正常结束，指令偏移归零。
低电流档不变，声音变化需要现场确认，不能把步幅倍数当作音量倍数。
三微步版DIR在STEP下降沿后切换，距离下一上升沿最短约84 µs。
TIM14相应提高边沿频率，保持音符的完整往返周期频率：
每周期6个STEP脉冲、12个定时中断边沿。

正常结束音符时，先完成当前正反一对，STEP低、DIR回初始方向、软件指令偏移为0，
再进入间隔/下一个音符。三微步版的指令偏移限制在0和+3微步之间，不朝一个方向持续走。
`MOTOR STATUS`的`offset`显示这一指令偏移。
**这不是编码器实测位置**；唤醒时的磁场对齐、机械共振或失步不能靠软件计数排除。

STOP、nFAULT、主循环250 ms无服务、播放总超时或脉冲上限都立即停止，不为了凑回原点继续驱动。
因此异常停止可能留下最多三步指令偏移，优先关闭输出。原来的`MOTOR RUN F/R`独立台架点动命令不属于音乐模式。

## 细分/静音限制

U2为DRV8434A，M0和M1直接接DRV_DVDD，固定1/8细分，未连接MCU。
当前硬件无可调用的软件静音开关，固件不能把细分改成整步。
DRV8434A的smart tune是内部电流衰减调节功能，不是当前可控的静音模式；
不更改STL_MODE/ENABLE含义来假装关闭静音，也不自动提高电流。

相邻微步往返幅度很小，1/8细分可能使声音仍然较轻。若需要试整步或改变细分，
必须先修改M0/M1硬件连接并重新核对电流和时序。参考：[TI DRV8434A手册](https://www.ti.com/lit/ds/symlink/drv8434a.pdf)。

## 验证边界

`notes_check.py --port YOUR_SERIAL_PORT`只发送CHECK、纯逻辑自测和故意无效的PLAY输入；
没有发送有效播放请求。检查解析、时长、升降号、休止符、边界拒绝、
正反结束边界及测试后仍处于禁用待机。
实际声音、机械摆幅及示波器波形需要用户就位后另行验证。
